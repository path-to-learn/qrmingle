Replit → Railway Migration Guide

Prepared May 2026  ·  Estimated effort: 30–45 minutes  ·  Risk level: Low

Why Migrate

Replit costs $20/month and requires a manual git pull in the shell to deploy. Railway costs ~$5–8/month and auto-deploys every time you push to GitHub — nothing else to do.

Monthly saving ~$12–15/month from day one

Is Your Database Tied to Replit?

No — you are safe. Your production database is already on Neon (neon.tech), which is fully external and independent of Replit. Your code reads NEON_DATABASE_URL first, which contains a neon.tech connection string. Replit's internal Postgres (DATABASE_URL, PGHOST, etc.) was never used in production.

This means zero data migration. Same database, same users, same profiles. Railway simply points at the same Neon URL that Replit already uses.

Your Replit secrets — what to keep and what to leave behind

Variable What it is Action
NEON_DATABASE_URL Your real production database on neon.tech Copy to Railway
SESSION_SECRET Signs user sessions Copy to Railway
STRIPE_SECRET_KEY Stripe payments backend key Copy to Railway
VITE_STRIPE_PUBLIC_KEY Stripe frontend key (used at build time) Copy to Railway
VITE_GA_MEASUREMENT_ID Google Analytics (used at build time) Copy to Railway
DATABASE_URL Replit's internal Postgres — not reachable outside Replit Leave behind
PGDATABASE, PGHOST, PGPORT, PGUSER, PGPASSWORD Replit auto-injects these for its internal DB — not used by your app Leave behind
NODE_ENV Must be set to production Add new on Railway
ANTHROPIC_API_KEY Required for AI Card Builder — get from console.anthropic.com Add new on Railway

How Dual Deployment Works

During migration you will briefly have two servers running, but they never serve the same domain simultaneously. DNS is the single switch that controls which server handles qrmingle.com.

Phase 1 — Today
qrmingle.com → Replit → Neon DB
Everything as normal. No changes yet.
↓
Phase 2 — Testing (a day or two)
qrmingle.com → Replit → Neon DB  ← real users, untouched
qrmingle-xyz.railway.app → Railway → same Neon DB  ← you testing here

Both servers share the same database safely. Any test account you create on the Railway URL appears in the live database — that is expected and fine.
↓
Phase 3 — DNS cutover (5 minutes)
qrmingle.com → Railway → Neon DB
One DNS record change at your domain registrar. Replit still runs but receives zero traffic. Monitor for 48 hours.
↓
Phase 4 — Done
Cancel Replit subscription. Railway is your only server from here on.

Step-by-Step Migration

Phase 1 — Set up Railway (30 minutes)

  1. 1
    Create Railway account Go to railway.app → Continue with GitHub → authorise access to your repos.
  2. 2
    New Project → Deploy from GitHub Select the qrmingle repository. Railway detects Node.js automatically.
  3. 3
    Set build and start commands In Railway dashboard → Settings → Build & Deploy: 
    Build command:  npm run build
Start command:  npm run start
  4. 4
    Add environment variables Railway dashboard → Variables → add each one: 
    # Copy from Replit
NEON_DATABASE_URL=your_neon_connection_string
SESSION_SECRET=your_session_secret
STRIPE_SECRET_KEY=sk_live_...
VITE_STRIPE_PUBLIC_KEY=pk_live_...
VITE_GA_MEASUREMENT_ID=G-XXXXXXX

# Add new
NODE_ENV=production
ANTHROPIC_API_KEY=sk-ant-...   # from console.anthropic.com
    Note on VITE_ variables Variables starting with VITE_ are embedded into the frontend at build time — not runtime. They must be present in Railway's env vars before the first build runs. Set them before clicking Deploy.
  5. 5
    Deploy and wait (~2 minutes) Railway builds your app. Watch the build log for errors. When complete, Railway gives you a URL like qrmingle-production.up.railway.app.

Phase 2 — Test on the Railway URL (1–2 days)

Use the *.railway.app URL to verify everything works before touching your domain. Go through this checklist:

  • Home page loads correctly
  • Register a new account
  • Log in / log out
  • Create a profile and add social links
  • QR code generates and scans correctly
  • Public profile page (/p/slug) loads for a visitor
  • AI Card Builder works (requires ANTHROPIC_API_KEY to be set)
  • Analytics page loads for a profile
  • Admin panel loads (log in as admin user)
  • Stripe payment flow (if active — can test with Stripe test mode)
  • No errors in Railway's log viewer

Phase 3 — DNS Cutover (5 minutes + propagation)

  1. 1
    Add custom domain in Railway Railway dashboard → Settings → Custom Domain → add qrmingle.com and www.qrmingle.com. Railway shows you a CNAME target (e.g. qrmingle.up.railway.app).
  2. 2
    Update DNS at your domain registrar Log into wherever you bought qrmingle.com → DNS settings → update the CNAME record for @ (root) and www to point to the Railway CNAME target.
  3. 3
    Wait for propagation Usually 5–30 minutes. Railway handles SSL automatically once the domain resolves. You can check propagation at dnschecker.org.
  4. 4
    Verify qrmingle.com loads from Railway Visit the site, check the Railway log for incoming requests. Replit is now idle.

Phase 4 — Update Stripe Webhook (5 minutes)

Only needed if Stripe payments are active Your Stripe webhook endpoint is currently registered to the Replit URL. After the DNS switch it resolves correctly through qrmingle.com so this may self-correct — but verify in the Stripe dashboard.

Stripe dashboard → Developers → Webhooks → confirm the endpoint URL is https://qrmingle.com/api/stripe-webhook. If it still shows a Replit URL, update it.

Phase 5 — Monitor then cancel Replit

  1. 1
    Monitor for 48 hours Watch Railway's log viewer. Check that users can sign up, log in, and use all features. Keep Replit running as a fallback (you can revert DNS in minutes if anything is wrong).
  2. 2
    Cancel Replit subscription Once confident: Replit dashboard → Account → Billing → cancel plan. You save $12–15/month from this point.

One Thing to Know: Uploaded Files

Tutorial videos are currently stored on Replit's local filesystem at /uploads/. Railway's filesystem is ephemeral — files are wiped on every deploy.

Recommended action (simple) There are very few admin-uploaded tutorial videos. After migration, simply re-upload them once through the admin panel. This takes 2 minutes and requires no code changes.

If this becomes a recurring pain (many uploads, frequent deploys), the proper fix is to store uploads in Cloudflare R2 or AWS S3. That is a ~2 hour dev task for later.

New Deployment Workflow After Migration

This is the biggest quality-of-life improvement. Today you SSH into Replit and run git pull. After Railway:

# That's it. Just push your code as normal.
git add .
git commit -m "your message"
git push origin main

# Railway detects the push, builds, and deploys automatically.
# Build takes ~90 seconds. Watch it live in the Railway dashboard.
# No shell access needed. No manual steps.

Every push to main is a production deploy. If you want to test before deploying to production, create a separate branch — Railway can be configured to only deploy from main.

Pre-Migration Checklist

  • Credit/debit card added to Railway for Hobby plan
  • All env var values copied from Replit Secrets panel (open in a text editor temporarily)
  • ANTHROPIC_API_KEY obtained from console.anthropic.com → API Keys

  • Build command set: npm run build
  • Start command set: npm run start
  • All 7 env vars added in Railway Variables panel

  • *.railway.app URL tested end-to-end

  • Home page loads correctly
